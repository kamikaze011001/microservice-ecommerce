# Local Kubernetes Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring up the existing 9-service microservice-ecommerce stack on a local kind cluster with seeded data, working ingress, HPA-driven stress testing, and 6 coworking checkpoints where the human writes the meaningful per-service decisions.

**Architecture:** kind cluster (1 control-plane + 3 workers), Helm-managed infra in the `infra` namespace (Bitnami MySQL/Mongo/Redis/MinIO/Kafka, Hashicorp Vault dev mode, ingress-nginx, kube-prometheus-stack), Kustomize-managed apps in the `apps` namespace, idempotent bootstrap Jobs that consume the existing `docker/*` seed files via `configMapGenerator`, all driven by new `make k8s-*` targets that coexist with the existing `make up` Compose flow. No `eureka-server` Pod — k8s DNS replaces it.

**Tech Stack:** kind, Docker, Helm 3, Kustomize (built into `kubectl`), Bitnami charts, hashicorp/vault chart, kube-prometheus-stack, ingress-nginx, k6, bash, GNU make.

**Spec:** `docs/superpowers/specs/2026-05-09-k8s-local-design.md`

**Note on TDD:** This plan is mostly DevOps-shaped work (manifests, Helm values, bash). "Write failing test first" maps to: `kubectl apply --dry-run=server` rejects the manifest until you write it correctly; `helm lint` fails until values are valid; smoke checks (`curl`, `kubectl wait`, `mysql -e`) fail until the system is up. Each task includes the validation step that proves the change works before committing.

**Coworking checkpoints:** 6 tasks (Tasks 13, 16, 23, 24, 26, 28) are explicitly marked `[CHECKPOINT — HUMAN]`. The AI must STOP at these, present the context and trade-offs to the human, and wait for the human to write the code before continuing to the next task.

- [ ] **Step 2: Write the registry bootstrap script**

Create `k8s/kind/registry.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

REG_NAME='kind-registry'
REG_PORT='5001'

# Start registry container if missing
if [ "$(docker inspect -f '{{.State.Running}}' "${REG_NAME}" 2>/dev/null || true)" != 'true' ]; then
  docker run -d --restart=always -p "127.0.0.1:${REG_PORT}:5000" --name "${REG_NAME}" registry:2
fi

# Connect registry to kind network if not already connected
if [ "$(docker network ls --filter name=kind -q)" ] && \
   [ "$(docker inspect -f='{{json .NetworkSettings.Networks.kind}}' ${REG_NAME})" = 'null' ]; then
  docker network connect kind "${REG_NAME}"
fi

# Document the registry to the cluster
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: ConfigMap
metadata:
  name: local-registry-hosting
  namespace: kube-public
data:
  localRegistryHosting.v1: |
    host: "localhost:${REG_PORT}"
    help: "https://kind.sigs.k8s.io/docs/user/local-registry/"
EOF

echo "registry running at localhost:${REG_PORT}"
```

- [ ] **Step 2: Write the build script**

Create `k8s/images/build.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

REGISTRY="${REGISTRY:-localhost:5001}"
TAG="${TAG:-dev}"

SERVICES=(
  authorization-server
  gateway
  inventory-service
  product-service
  order-service
  payment-service
  orchestrator-service
  bff-service
)

if [ -n "${SVC:-}" ]; then
  SERVICES=("$SVC")
fi

cd "$(git rev-parse --show-toplevel)"

for svc in "${SERVICES[@]}"; do
  echo "==> building ${svc}"
  docker build \
    -f k8s/images/Dockerfile.jvm \
    --build-arg SERVICE="${svc}" \
    -t "${REGISTRY}/${svc}:${TAG}" \
    .
  docker push "${REGISTRY}/${svc}:${TAG}"
done
```

### Task 12: MySQL seed Job (idempotency reference example)

**Files:**
- Create: `k8s/infra/jobs/01-mysql-seed/job.yaml`
- Create: `k8s/infra/jobs/01-mysql-seed/seed.sh`
- Create: `k8s/infra/jobs/01-mysql-seed/kustomization.yaml`

- [ ] **Step 1: Write the seed script**

Create `k8s/infra/jobs/01-mysql-seed/seed.sh`:

```bash
#!/usr/bin/env sh
set -eu

# Idempotency check: count tables in the target schema. If > 0, skip.
TABLE_COUNT=$(mysql -h mysql.infra.svc.cluster.local -uroot -p"${MYSQL_ROOT_PASSWORD}" \
  -N -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='ecommerce_dev';")

if [ "${TABLE_COUNT}" -gt 0 ]; then
  echo "mysql already seeded (${TABLE_COUNT} tables present); skipping"
  exit 0
fi

echo "seeding mysql..."
mysql -h mysql.infra.svc.cluster.local -uroot -p"${MYSQL_ROOT_PASSWORD}" \
  ecommerce_dev < /seed/ecommerce.sql
echo "mysql seed complete"
```

- [ ] **Step 2: Write the Job manifest**

Create `k8s/infra/jobs/01-mysql-seed/job.yaml`:

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: mysql-seed
  namespace: bootstrap
spec:
  backoffLimit: 3
  ttlSecondsAfterFinished: 600
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: seed
          image: bitnami/mysql:8.0
          env:
            - name: MYSQL_ROOT_PASSWORD
              value: root
          command: ["/bin/sh", "/scripts/seed.sh"]
          volumeMounts:
            - name: scripts
              mountPath: /scripts
            - name: sql
              mountPath: /seed
      volumes:
        - name: scripts
```

```markdown
# k8s/ — Local Kubernetes setup

Runs the full microservice stack on a 4-node kind cluster. See the design spec at

## Quick start

    make k8s-bootstrap        # one-time
    make k8s-status

    make k8s-up               # apply current overlay
    make k8s-down             # delete cluster (full reset)

    make k8s-logs svc=order-service
    make k8s-stress           # run k6

## Layout

- `kind/` — cluster config + local registry script
- `infra/` — Helm values + bootstrap Jobs
- `apps/` — Kustomize bases (one per service) + overlays (`local`, `aws`, `local-with-frontend`)
- `images/` — Dockerfile template + build script

## Coexists with `make up`

The Docker Compose dev workflow (`make up`) is unchanged. The two environments are
fully independent — `make up` and `make k8s-up` use different Pods/containers and
data volumes. Eureka runs only in compose; k8s uses k8s DNS.

## What's local-only

- MySQL is single-node (Bitnami chart, replicas=1) but exposes both `mysql-primary`
  and `mysql-replica` Service names so app DSNs match the prod-shape from day one.
- Vault is in dev mode (auto-unsealed, root token = `root`). Production swap: real
  Vault deploy or AWS Secrets Manager + External Secrets Operator.
- MinIO stands in for S3. Production swap: flip `secret/core-s3` to point at AWS S3.
```
