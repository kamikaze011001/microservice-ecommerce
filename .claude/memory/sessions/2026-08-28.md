# 2026-08-21→28 — `ENV=aws` actually ran

PR #64 merged (`320467d`), 21 commits. The AWS path had never executed in five phases
of shipping it. It has now, twice, for roughly **$6–8** total.

## What happened

**Session 1** died at `aws_acm_certificate_validation` after 1h15m. Root cause was
four layers up from AWS: `microecom.click` carried a registrar **`clientHold`** (ICANN
registrant email never confirmed), so the `.click` registry had withheld the domain
from the zone file entirely. Hosted zone present, nameservers matching, validation
CNAME written — all invisible, because nothing outside AWS could resolve the domain.
Every check *inside* the account said healthy.

**Session 2** reached a live cluster with all nine services deployed.

## The finding that matters

`deploy/scripts/aws-deploy.sh` had `--set infra.enabled=false` **inline in its
`--mode render` branch only**. The real apply execs `make k8s-apps-helm`, whose recipe
composes its own helm call from `$(HELM_EXTRA)`. So `make aws-diff-test` — the gate
five phases relied on — validated a command the live path never issues
([[an-oracle-can-validate-a-command-nobody-runs]]).

Live, the umbrella tried to create a `grafana` ServiceAccount owned by the separate
release `infra-up.sh` installs. Had it *succeeded* it would have been worse: the
`microecom` release would own the infra objects, arming exactly the deletion trap
[[0005-aws-infra-stays-outside-the-umbrella-chart]] exists to prevent.

## Reading vs running

Three blockers were found offline, for free, by reading scripts. Each would have cost
a live session. **But the worst defect was structurally invisible to reading**, because
both branches of `aws-deploy.sh` are individually correct — the bug lives in the
relationship between them and a Makefile recipe one of them execs.

Reading eliminates failures that live in a file. Only running eliminates the ones that
live between files.

## Controller errors worth remembering

- **Four of the branch's own defects were introduced by the branch** — the plan's
  `errexit` bug, a recovery message naming a nonexistent cluster, `PUSH=all`, and the
  spec's D3 that seeded it. New text is the least-reviewed text in a repo.
- **The mail verdict was verified wrong**, not merely unlucky: it read a golden
  generated from test fixtures ([[a-golden-fixture-proves-the-renderer-not-the-inputs]]).
- **A stale CNAME check produced a false negative.** I handed over a validation record
  name captured before a teardown that deletes it — a check keyed to a destroyed
  resource can only return empty, so it tests nothing.
- **`cat a b > c` with `a` missing** printed an error, continued, exited 0, and I used
  the result to overwrite a PR description. Partial success reporting as success —
  the same class the branch spent six commits on.
