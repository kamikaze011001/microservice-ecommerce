## Controller error worth remembering

The Task 2 fix I wrote into the plan was itself broken: three distinct exit codes read via
a bare call under `set -euo pipefail`, so every diagnostic branch was unreachable
([[errexit-consumes-a-functions-exit-code]]). It passed `bash -n` and the full unit suite.
The implementer caught it, transcribed the plan faithfully anyway, and flagged it — the
right behaviour, and the reason it was caught at all.

Note the shape: the bug being fixed was `|| true` merging two distinct failure meanings.
The fix separated them into three codes, then collapsed all three via shell semantics.
**Same defect, one layer up, in the code written to prevent it.**
