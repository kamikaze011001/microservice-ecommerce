## The pattern across all three PRs

Three times a check passed while proving nothing: a suite reading a deleted file, a mutation
test perturbing an uncalled function, and [[a-grep-gate-tests-for-strings-not-for-currency]].
What caught all three was never "run the tests again" — it was asking what the measurement
would show if the thing measured were absent, then arranging for the answer to differ. Mocking
`ifconfig` to force an empty set; instrumenting the call to count round-trips; `git show`-ing
a deleted file rather than recalling what it did.

**A green result is only evidence if you know what red would have looked like.**

## Controller errors worth remembering

Four corrections in PR #60 were to the **plan**, not to implementer work — a false ordering
comment, a `kill` written fresh while a correct one sat in `stop.sh`, a grep gate too narrow
to see a diagram, and a minio mapping I had already gotten wrong once in Phase 8 and written
the warning about myself. Implementers transcribe briefs verbatim by design, so an unchecked
claim in a plan becomes an unchecked claim in the repo. **Plan prose needs the same
verification as plan code**; self-review currently looks for placeholders and name
consistency, not factual claims.

Also: two plans contained hedges ("use whatever the file actually defines", "or it may
accidentally pass") that read as humility and were deferred homework — steps whose expected
outcome had not been computed. Both were removable with one command.
