## The plan was wrong, and catching it was the point

A reference sweep **before** the deletion task found four live callers still reading the
doomed trees, including `make up`. All six offline suites passed at that moment, so the
plan's own precondition would have authorised deleting anyway.

`verb-equivalence` compares `make -n` expansions against baselines captured from those same
expansions — it proves nothing *changed*, and was silently doing duty as proof something was
*safe to delete*. Different claims; the gap is invisible while everything is green.

Root cause: **`k8s/` was two things under one directory name.** Helm replaced the *apps*
layer (Task 1 verified it live); nothing replaced the *infra-bootstrap* layer, because the
chart ported the StatefulSets but not the Jobs that initialise them.

## Six real bugs, in two distinct classes

**Three found by the live gate** — each needs a *second* event to exist, so no first install
could reach them: [[deployment-progress-deadline-preempts-helm-timeout]],
[[helm-subchart-toggle-deletes-on-a-shared-release]],
[[hpa-managed-deployments-must-not-declare-replicas]]. Cost: a ~25min cluster rebuild each.

**Three found by the final review** — scripts the Makefile *calls* still reading deleted
paths ([[make-n-shows-commands-not-the-files-they-read]]). Cost: one repo-wide grep. One of
them broke `make bootstrap ENV=k8s` at its first step — the exact path the gate had certified,
because the gate ran before the deletion and the post-deletion check only inspected the
already-running cluster.

Worth keeping these classes separate: one needs expensive execution, the other needs a plain
search, and conflating them means over-investing in cluster runs to catch what grep handles.
