## Decisions
- `0004-canonical-secrets-resolve-transport-split` — one canonical file per service, pure resolver
  separated from transport, so every env (including aws) is verifiable offline without credentials.
- Six design choices settled by the user: all three envs with aws verified offline; always
  overwrite; cached terraform-outputs JSON; explicit `envs:` on non-universal keys; preserve
  today's credential split but make it explicit; compose leg of the live check now, k8s later.

## Conventions captured
- `vault-config-comment-keys-are-really-seeded` — `_comment*` keys were never comments; they have
  always been live Vault properties. Explains the 94-vs-90 key count.
- `cross-env-equality-checks-miss-shared-drift` — "all envs agree" is a relative invariant; it
  stays green when a shared source file moves all three at once. Two instances found, both mine.
- `k8s-targets-inherit-ambient-kubectl-context` — kubectl pointed at an unrelated live cluster;
  the seeder now refuses an unnamed context.

## Worth remembering about the process
- The plan was wrong four times and each was caught by the *implementer*, not shipped: a missing
  `jq -c` that shredded the AWS capture format, an `orthaned`/`orphaned` typo that would have made
  a test pass vacuously, a comment naming the wrong file for the Vault token, and a baseline
  expectation that didn't match reality.
- The strongest evidence in the branch was unplanned — Vault KV v2 retains versions, so the old
  seed was still on the same backend, turning an offline "resolver matches capture" into a live
  "old write vs new write differ by exactly four inert keys".
